Known limitations

  • No git-diff/changed-files scanning here — every scan is a full pass over whatever folder you give it. (The downloadable desktop app has a git changed-files mode.)
  • An unquoted YAML value's mask isn't force-quoted the way the desktop app does it. A bare * is YAML's alias syntax, so redacting an unquoted YAML scalar can, in rare cases, produce invalid YAML.
  • Scan history, the ignore list, and any rule edits are stored only in this one browser, on this one device — nothing syncs across browsers or devices, and it's lost if you clear this site's browser data.
  • Sanitizing is a deliberate multi-step flow: filter which files to scan → review/ignore findings (and "Scan again" to refresh, if needed) → "Generate sanitized file" → "Download" appears for that specific generated copy. Changing anything afterward — an ignore, a restore, or another scan — marks that generated copy stale and requires regenerating before you can download.
  • "Scan again" re-reads the folder fresh from disk only when it was opened via "Remember a folder for next time" (Chrome/Edge's File System Access API). For a folder provided by drag-and-drop or "Choose folder," there's no way to silently re-read it, so "Scan again" re-scans the same in-memory copy — edits made on disk since then won't be reflected until you choose the folder again.

This browser version covers single-line detection across config files and code, plus multi-line concatenated secrets in Python, Java, JavaScript/TypeScript, C#, and Go (both var name Type = "..." and name := "..." forms, matching the desktop app). For project history, use the downloadable app.
